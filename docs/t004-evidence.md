## Implemented boundaries

- Browser drafts include owner, document, acknowledged baseline, schema version and 24-hour expiry. Recovery is a choice. Blocked storage cannot produce a “saved on this device” claim.
- Confirmation deduplicates an immutable flow payload. A lost response can be retried without creating another CV. Invalid, foreign or stale accepted facts roll back the entire transaction, including snapshots and links. Reusing confirmed master values does not accept proposed changes; local CV edits do not update master facts.
- PDF input remains native and bounded to 25 MB / 30 pages; partial extraction is disclosed. File handoff is owner/flow scoped, expires and is claimed once. Original attachments are never passed to a model. Word attachment and legacy contact-bearing semantic-review routes fail before provider access.
- Browser preview/check/download reuse an immutable, bounded, owner-scoped artifact. SHA-256 describes the generated Blob bytes. Hover/history/old-owner renders cannot publish the selected artifact. Server export tokens bind a persisted revision and independently hash their generated bytes.
- `/pdf-checks` now requires authentication, a current owned non-trashed CV and an artifact identity. The server recomputes the uploaded-byte hash and checks ownership/revision before and after extraction. An uploaded file is not falsely certified as a server-generated rendering of CV data. No file, raw extraction or private report cache is persisted.
- The checker landing page opens the private workspace. Public upload, sharing and assistant launchers are absent from the mapped CV flow. Selected-job evidence and semantic AI review remain unavailable until their scheduled dependencies.
