## Status and authority

Evidence and decisions have different authority:

| Label         | Meaning                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| UC            | User-confirmed context or instruction from this conversation                                                                               |
| USER-SELECTED | Explicit user choice, used for the Moyasar provider decision; not a supplier contract, merchant activation or independently verified claim |
| OD            | Requirement or proposal in the original supplied draft; not automatically approved                                                         |
| REC           | Our recommended product decision; awaiting acceptance                                                                                      |
| OPEN          | Decision, evidence, or commercial condition still unresolved                                                                               |
| OBS           | Behavior observed in supplied code or a public source; the observation date and limits matter                                              |
| WORKING       | Latest agreed conversational direction, not proof of implementation or final owner/merchant/legal approval                                 |
| APPROVED      | An explicit decision by the relevant project owner, with its date recorded; D01 now records the confirmed personal-only initial MVP        |

**OWNER DECIDED 2026-11-04** records product direction only. It does not approve implementation, activation or release; A01-A16 and the listed company inputs still apply.

### D31 export display follow-up — 2026-11-07 / Round 9

PDF display detects conservative ordered numeric date ranges in plain and rich free text, including repeated Hijri `هـ` suffixes and `من … إلى/حتى …` labels. It displays Western digits and an ASCII hyphen-minus without spaces between endpoints (`1440-1441 هـ`, `2010-2012`); suffix/label words remain separate display runs. Repeated identical Hijri calendar suffixes are displayed once, with no calendar conversion. Only numeric endpoints with matching precision, valid components and plausible ascending years are considered; phones, URLs, identifiers, mixed calendars and descending ranges are left alone. Saved CV facts are unchanged. In the current renderer, changed ranges occupy a separate line to preserve both readers; this can increase document height.

This authorized display rule does not change D32, fact-level v2, strict v1 or frozen gold. Frozen source-shaped assertions may therefore fail on the changed punctuation/label placement; record those failures and assess fact loss separately, without silently certifying a pass.
